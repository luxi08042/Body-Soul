## 诊断1：图片裂图 + 聊天弹窗背景空白

### 根因
`backend/backend/settings.py` 中 `DEBUG = False`，导致两个后果：
1. `MEDIA_URL = 'https://app7492.acapp.acwing.com.cn/media/'`，`FieldFile.url` 生成线上绝对地址，
   但图片实际只在本地 `backend/media/`，线上服务器无这些文件 → 全部 404
2. `backend/backend/urls.py` 末尾 `if settings.DEBUG:` 块不执行，`/media/` 路由未注册

- 截图作者行显示 "1 kx" 是浏览器裂图占位符，非真实数据

**用户已自行采用方案A（DEBUG = True），问题解决。**

## 诊断2：发消息 AI 不回复 + 语音发不出

### 根因（必崩点）
`chat.py` 原第 178 行：
```python
thread = threading.Thread(target=self.work, args=(app, inputs, mq, friend.character.voice.voice_id))
```
`web_voice` 表 **0 行**，所有 `character.voice_id` 均为 NULL → `friend.character.voice` 是 None
→ `None.voice_id` 抛 AttributeError → 生成器启动即崩，LLM 从未被调用

连带：前端 `InputField.vue` 的 `onerror`/`catch` 都是空函数，静默吞错，所以界面无任何报错痕迹。
语音发不出是同一原因：ASR 转写成功后 → handleSend → 同一个 chat 接口 → 同样崩。

## 变更：chat.py 移除 TTS，改为纯文本流（已实施）

用户问「把所有的 voice 都注释掉可以吗」—— 可以，但不能纯注释，
因为 `tts_sender` 里同时承载了 LLM 的 astream 循环，注释掉会导致 AI 也不回复。
做法：保留 LLM 循环，剥离 TTS 相关代码。

`backend/web/views/friend/message/chat/chat.py` 改动：
- imports 移除 `base64`、`os`、`uuid`、`websockets`（保留 asyncio/json/threading/Queue）
- `tts_sender` → `chat_sender`：去掉 `await ws.send(...)`，只保留 `mq.put_nowait({'content':...})`
- 删除 `tts_receiver`（纯接收音频）
- 删除 `run_tts_tasks`（websocket 建连 + SpeechSynthesizer 任务下发）
- `work(app, inputs, mq, voice_id)` → `work(app, inputs, mq)`，内部调 `run_chat_task`
- 新增 `run_chat_task(app, inputs, mq)` 包一层，便于将来恢复 TTS
- `event_stream` 不再传 `friend.character.voice.voice_id`（崩溃点消除）

保留项：`msg.get('audio')` 分支留着，纯文本模式下永不为真，不影响；
前端 `initAudioStream`/`handleAudioChunk` 同理，留着无害。
`py_compile` 语法检查通过，无 voice/tts/websocket 残留引用。
